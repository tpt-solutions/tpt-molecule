tpt-molecule Design Specification (v0.1)
1. Overview
tpt-molecule is a pure Rust, high-performance cheminformatics and molecular dynamics engine. It serves as the unified, zero-FFI replacement for RDKit (molecular graph manipulation, SMILES/SMARTS parsing, fingerprinting) and OpenMM (GPU-accelerated force fields, energy minimization, and time integration).
By combining discrete molecular graph mathematics (RDKit) and continuous physical simulation (OpenMM) into a single workspace, tpt-molecule eliminates the fragile FFI boundaries that plague traditional drug discovery pipelines. It leverages tpt-math for numerical optimization and utilizes wgpu compute shaders to deliver cross-platform, zero-C++-dependency GPU acceleration.
2. Design Goals
Strict Permissive Licensing: Every dependency must be MIT, BSD, Zlib, Unicode, ISC, or Dual MIT/Apache-2.0. GPL, LGPL, AGPL, MPL, and "Apache-2.0 ONLY" crates are strictly banned.
Zero-FFI & Memory Safety: No bindgen wrappers for C++ libraries (like RDKit, OpenBabel, or OpenMM). All molecular parsing, graph traversal, and physics kernels are written in safe Rust.
Cross-Platform GPU Compute: Unlike OpenMM, which relies on proprietary CUDA toolchains and C++ FFI, tpt-molecule uses wgpu (WebGPU) compute shaders. This allows molecular dynamics to run on NVIDIA, AMD, Apple Silicon, and even in the browser via WebAssembly, without requiring the NVCC compiler.
no_std Core: The foundational graph theory and periodic table math (tpt-molecule-core) must support no_std + alloc for deployment on edge diagnostic devices or embedded lab automation.
Fearless Concurrency: Substructure searching across millions of compounds and N-body force calculations are highly parallelizable. The architecture uses rayon and wgpu dispatches to maximize throughput without data races.

4. Crate Breakdown
4.1 tpt-molecule-core (The Foundation)
Role: The no_std leaf crate. Contains the periodic table, atomic masses, van der Waals radii, physical constants (Boltzmann, Avogadro), and basic unit conversions.
Dependencies: tpt-math (Internal).
4.2 tpt-molecule-graph (The RDKit Killer)
Role: Handles discrete molecular topology and cheminformatics.
Key Features:
Parsing: Pure Rust, zero-copy parsers for SMILES, SMARTS, SDF, and MOL2 formats.
Graph Engine: Built on top of petgraph (MIT/Apache-2.0), representing atoms as nodes and bonds as edges with rich metadata (aromaticity, stereochemistry, chirality).
Substructure Search: Highly optimized VF2 algorithm implementation for matching SMARTS patterns against massive compound libraries.
Fingerprints: Morgan (ECFP), MACCS keys, and topological torsion fingerprints for machine learning and similarity searching.
Dependencies: petgraph (MIT/Apache-2.0), tpt-molecule-core, tpt-simd (Internal, for vectorized fingerprint Tanimoto calculations).
4.3 tpt-molecule-dynamics (The OpenMM Killer)
Role: The computational physics engine for simulating molecular behavior over time.
Key Features:
Force Fields: Pure Rust implementations of AMBER, CHARMM, and OPLS force fields (bond stretching, angle bending, torsions, Lennard-Jones, Coulombic).
Integration: Velocity Verlet, Langevin, and Nose-Hoover thermostats.
Energy Minization: L-BFGS and conjugate gradient algorithms (powered by tpt-math) to relax 3D coordinates generated from 2D SMILES.
Dependencies: tpt-molecule-core, tpt-math (Internal), rand (MIT/Apache-2.0, for stochastic Langevin forces).
4.4 tpt-molecule-compute (The GPU Accelerator)
Role: Offloads the most computationally expensive parts of MD (non-bonded force calculations) to the GPU.
Key Features:
wgpu Compute Shaders: Written in WGSL, these shaders calculate pairwise Lennard-Jones and electrostatic interactions.

6. Key Technical Decisions (ADRs)
ADR-001: Pure Rust SMILES/SMARTS over FFI to OpenBabel
Decision: We will write our own SMILES and SMARTS parsers rather than wrapping OpenBabel or RDKit.
Rationale: OpenBabel is GPL, which instantly contaminates the workspace. RDKit requires heavy C++ FFI. By implementing a pure Rust recursive-descent parser for chemical line notations, we maintain zero-FFI, strict MIT compliance, and eliminate cross-compilation nightmares.
ADR-002: WebGPU (wgpu) for Molecular Dynamics Compute
Decision: Non-bonded force calculations (the bottleneck of MD) will be offloaded to the GPU using wgpu compute shaders written in WGSL, rather than using CUDA or OpenCL C++.
Rationale: OpenMM relies on the proprietary NVIDIA CUDA toolkit and C++ compilers. By using wgpu, tpt-molecule achieves cross-platform GPU acceleration (NVIDIA, AMD, Apple Metal, Vulkan) without requiring the user to install C++ build tools or proprietary drivers. It also opens the door to running MD simulations directly in the browser via WebAssembly.
ADR-003: Graph-Based Substructure Search via petgraph
Decision: Substructure matching will use the VF2 algorithm implemented on top of petgraph.
Rationale: RDKit's substructure search is written in complex C++. petgraph provides a safe, idiomatic Rust graph abstraction. Implementing VF2 in safe Rust allows us to easily parallelize the search across millions of molecules using rayon without worrying about C++ pointer invalidation.
7. Data Flow Example: Structure-Based Drug Discovery
To illustrate how the workspace operates, here is the data flow for a typical virtual screening pipeline:
Ingestion (tpt-molecule-graph): Reads a library of 10 million compounds in SMILES format. Parses them into molecular graphs in parallel using rayon.
Filtering (tpt-molecule-graph + tpt-simd): Calculates Morgan fingerprints and uses SIMD-accelerated Tanimoto similarity to filter the library down to 100,000 drug-like candidates.
3D Coordinate Generation (tpt-molecule-dynamics + tpt-math): Converts the 2D graphs into 3D coordinates using distance geometry, then runs a rapid L-BFGS energy minimization to relax steric clashes.
GPU Simulation (tpt-molecule-compute + tpt-molecule-dynamics): Uploads the 3D coordinates to the GPU via wgpu. Runs a 10-nanosecond Molecular Dynamics simulation using the AMBER force field and Langevin thermostat to observe protein-ligand binding stability.
Analysis (tpt-molecule-dynamics): Calculates the root-mean-square deviation (RMSD) and binding free energy estimates.
Export (tpt-molecule-py): The top 100 binding candidates are exposed to a Python Jupyter notebook via PyO3 for final visualization and reporting.
8. Phased Roadmap (Solo Maintainer Strategy)
Phase 1: Core & Graph Engine (Months 1-3)
Scaffold the Cargo workspace.
Implement tpt-molecule-core (periodic table, physical constants).
Implement tpt-molecule-graph: SMILES parsing, basic molecular graph construction, and Morgan fingerprint generation.
Milestone: tptmol search can parse 1 million SMILES strings and calculate fingerprints faster than RDKit.
Phase 2: Physics & Minimization (Months 4-6)
Implement tpt-molecule-dynamics: AMBER force field parameterization, bond/angle/torsion energy calculations.
Integrate tpt-math for L-BFGS energy minimization.
Implement Velocity Verlet integration for basic CPU-only MD.
Milestone: tptmol minimize can generate stable 3D coordinates from 2D SMILES without steric clashes.
Phase 3: GPU Acceleration (Months 7-9)
Implement tpt-molecule-compute: Write WGSL compute shaders for Lennard-Jones and Coulombic pairwise forces.
Implement cell-list neighbor algorithms in compute shaders.
Milestone: tptmol simulate can run a 10,000-atom system at nanoseconds-per-day speeds on a mid-range GPU, entirely without CUDA C++.
Phase 4: CLI, Python Bindings & Release (Months 10-12)
Build tpt-molecule-cli frontend.
Implement tpt-molecule-py (PyO3).
Milestone: Release v0.1.0 on crates.io and PyPI. Publish benchmarks comparing tpt-molecule to RDKit and OpenMM.
